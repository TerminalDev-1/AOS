# AOS architecture

AOS boots through x86-64 UEFI. `aos/src/main.rs` is the loader: it includes
the kernel ELF and clean FAT12 data seed, obtains the GOP framebuffer, exits
boot services and passes a versioned boot structure to the kernel. The kernel
in `aos/kernel/src/` installs its own page tables and runs independently of
UEFI boot services. It drives the framebuffer, PIT timer, PS/2 keyboard and
mouse, serial ports and IDE storage. The desktop is currently drawn in
software directly into the framebuffer.

The live ISO contains a UEFI El Torito boot volume and the seed data volume.
When no IDE data disk is attached, the kernel uses a writable RAM copy of the
seed. Installed mode uses an MBR image with a FAT16 EFI partition and a FAT12
data partition. Both modes use the same desktop and native `.AIS` applications.
The seed is generated by `aos/seed.py`; there is no BIOS boot sector or
dependency on the removed 16-bit edition.

Programs uses a versioned `AIS64` header inside `.AIS` files and maps native
x86-64 code and stack pages under a separate user page-table root. The first
ABI supports exit and text output through `INT 80h`; apps are single-tasked,
with a fault handler and time limit. The host-side Store sends a small native
catalogue over COM2.

The AOS shell has a full-width light taskbar, rounded Start menu, app-name search,
pinned launchers and window controls. It keeps the smooth purple/blue wallpaper
and rounded light windows. The taskbar and Start menu are drawn off-screen and
copied as completed frames. Start preserves its underlying image between
repaints, so translucent shadows do not accumulate. It is a shell overlay and can
launch the existing built-in applications. The UEFI loader displays a large
red AOS splash before it loads the kernel ELF. The core remains written in
Rust with assembly for low-level CPU operations.

The desktop, editors, file driver and Store UI currently execute in kernel
space. There is no hardware graphics acceleration, separate compositor,
network stack, concurrent process scheduler or in-system package repository.
The implementation has been exercised in QEMU/EDK2 only.
